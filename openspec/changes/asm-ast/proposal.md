# Proposal: Asm AST — ассемблер в AST-графах (`asm-ast`)

## Проблема

Ассемблерные файлы (`.s`, `.S`, `.asm`) полностью невидимы для AST-сканера: их
нет в реестре `LANGS` (Ф47.1), поэтому `collect_files` пропускает их, вотчер
игнорирует (`is_code_file` = `LangSpec::for_path`), а `project_impact` /
`project_call_path` / `repo_map` не видят символы. При этом критичные части
реальных проектов живут именно в ассемблере: ядра и загрузчики (Linux
`arch/*/boot/*.S`), крипто-примитивы (`aesni`, `sha512` в libc/musl/boringssl),
hot-path библиотеки (`__memcpy_avx`), reverse-инжиниринг и CTF-проекты,
inline-asm вынесенный в отдельные unit-файлы. Разрыв графа на этих файлах даёт
ложный «blast radius = 0» и обрыв цепочек вызовов C → asm.

## Решение

Добавить ассемблер двумя волнами по сложившемуся паттерну репозитория:

1. **Regex-волна (Фаза 78, как Ф48–Ф52 для прочих форматов)** — две записи
   `LangSpec` (`asm-gas` для `.s`/`.S`, `asm-intel` для `.asm`), сниффинг диалекта
   по контенту (GAS AT&T / GAS Intel / NASM / MASM), экстрактор `Parser::Asm`:
   метки и `PROC/ENDP` → `Function`, макросы → `Macro`, данные/константы →
   `Data`, `include`-директивы → `IMPORTS`, `call`/`jal`/`bl` → call_sites с
   последующим `CALLS`-резолвом через существующий type-pass. Skip-листы против
   шума локальных/компиляторных меток.
2. **Tree-sitter-волна (Фаза 78b, как Ф70.3–70.6)** — грамматика
   `tree-sitter-asm` (crates.io, RubixDev, generic asm) под фичей `treesitter`
   для GAS-диалектов; NASM/MASM остаются на regex (грамматик на crates.io нет).
   Инкрементальный парсинг (Ф70.8) и ERROR-fallback (Ф70.9) переиспользуются
   без изменений.

## Результат

- `.s`/`.S`/`.asm` сканируются, вотчатся и инкрементально пересканируются.
- Словари asm-форматов в реестре; инвариант консистентности Ф47.5 и единство
  обходчика/вотчера Ф47.2 проверяются автоматически фикстурами реестра.
- Golden-эталоны `asm-gas` / `asm-nasm` / `asm-masm` (гейты: symbol F1 ≥ 0.95,
  call F1 ≥ 0.90) — семантика языка зафиксирована независимо от бэкенда.
- Кросс-языковые цепочки C → asm и asm → asm в `project_call_path`.

## Не-цели

- CFG-рёбра по условным/безусловным переходам (`jmp`/`jcc`/`b`) — внутрипроцедурный
  шум, раздувает граф; возможная будущая фаза за флагом.
- Дизассемблирование бинарников — только исходники.
- Разрешение косвенных вызовов (`call *%rax`, `call rax`) — статически не
  разрешимо, пропускаем (как и все прочие языки).
- Generated-stub маски (Ф70.15) для `.s` — вывод компилятора в репозиториях
  редок; отложено до реальных кейсов.
