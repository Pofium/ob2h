# План разработки OB2H v2.0: Next-Gen Retrieval & Polyglot AST Engine

> **Версия плана:** 2.0.0 (Мажорный архитектурный релиз)  
> **Статус:** Черновик к обсуждению и утверждению (Синтез рецензий v2.0 + Enterprise Lifecycle Installer & Uninstaller Suite)  
> **Дата формирования:** 2026-10-25  
> **Базовое состояние:** v1.8.0 (опубликованный релиз) / v1.9.0-dev (Secrets Vault, Ralph Knowledge Layer, FTS5 Graph, LRU-кэш в `main`)  
> **Принцип совместимости и архитектурные границы:**  
> - Сохранение **ADR-1..8**: SQLite — единственная СУБД; никаких внешних серверов/демонов (Neo4j, Redis, Docker).  
> - Сохранение возможности **zero-dependency чистой сборки** (Candle + Regex fallback по умолчанию, компилятор C++ не требуется).  
> - Полная обратная совместимость схемы БД: автоматическая миграция **M10** (`SCHEMA_VERSION = 10`) с предварительным бэкапом и поддержкой dry-run.  
> - Аддитивное расширение MCP-контракта (существующие 41 инструмент сохраняют сигнатуры и семантику).  
> - **Честная политика Offline / LLM:** 100% локальное исполнение для парсинга AST, вычисления эмбеддингов, векторного поиска и графовых алгоритмов (U-PPR). Для LLM-операций дистилляции знаний (консолидация в Dream) предоставляется два режима: внешний API (DeepSeek/OpenAI), либо полностью автономный offline-режим (эвристические правила + косинусная семантическая близость без LLM).

## 1. Мотивация и предпосылки

К версии v1.9 `ob2h` сформировался как полнофункциональное персональное хранилище знаний, секретов и AST-графа проектов для AI-агентов. Однако при масштабировании на крупные кодовые базы (100k+ LOC), базы знаний (50k+ фактов) и широкий спектр рабочих окружений выявились архитектурные границы существующих решений:

| Компонент v1.x | Текущая реализация (As-Is) | Ограничение при росте | Целевое состояние v2.0 (To-Be) |
|---|---|---|---|
| **AST Parser** | Линейный regex/bracket-парсер | Не видит сложные цепочки вызовов `.foo().bar()`, макросы, типы в выражениях | **Tree-sitter Hybrid Engine** для топ-4 языков (Rust, TS/JS, Python, Go) с regex-fallback; `provenance` и `confidence` на рёбрах |
| **Embeddings** | Candle CPU (чистый Rust) + LRU-кэш | Холодный поштучный расчет 50–80 мс на CPU; синхронная блокировка Tokio | **FastEmbed / ONNX Runtime (INT8)** за feature-флагом, фоновый воркер-пул (`spawn_blocking`), батчи 32/64 чанка |
| **Vector Storage** | Линейный BLOB-скан + Cosine RRF | При >50k векторов O(N) перебор дает задержки >50 мс | **sqlite-vec / SIMD-ускорение**, инкрементальный upsert, двухступенчатый отбор (SIMD oversample $\to$ float rescore) |
| **Graph Retrieval** | BFS на $k$ шагов + FTS5 + векторный поиск | Нет ранжирования по живому опыту агента; шумные узлы не отсекаются | **Usage-Weighted PPR** с защитой от петли популярности, затуханием по типу сущности, CATD-lite и сабграф-кэшированием |
| **Жизненный цикл знаний** | Ручные пометки или простой decay | Накопление устаревших и конфликтующих фактов; split-brain агента | **Консолидация в Dream (3 типа конфликтов)**: `SUPERSEDES`/`CONTRADICTS`, HITL-preview, tombstone-семантика |
| **Agent Loop Integrity** | Разрозненные точки доступа к графу | PPR не видит реальные обращения из prefetch/Ralph; findings устаревают | **Access Telemetry Parity** по всем инструментам агента + авто-инвалидация устаревших findings Ralph при смене AST |
| **Установка и деинсталляция** | Ручная сборка `cargo build` или сырой архив, ручная настройка путей и MCP, неполное удаление | Высокий порог входа, поломка рантайм-зависимостей (VC++, glibc), мусор в реестре/PATH, поломка конфигов IDE при сносе | **Инсталлятор и деинсталлятор полного цикла уровня Adobe/JetBrains**: нативные визарды (Inno/MSI, PKG/DMG, deb/rpm), фоновые демоны, zero-touch IDE setup, Adobe-style Cleaner Tool с управлением БД |

## 2. Ключевые архитектурные столпы v2.0

### Столп I: Гибридный полиглотный AST-движок (Tree-sitter + Regex)
- **Ядро:** Интеграция `tree-sitter` (0.27.x) через `tree-sitter-language` под опциональным feature-флагом `treesitter` для 4 основных языков: Rust, TypeScript/JavaScript, Python, Go.
- **Fallback:** Существующий линейный regex-парсер сохраняется для остальных 15+ языков, а также включается при синтаксических ошибках (доля `ERROR`-узлов в CST > 10%).
- **CST vs Semantics:** Tree-sitter дает конкретное синтаксическое дерево (CST), но не вывод типов. Для графа вызовов вводится типизация достоверности связей (`provenance`):
  - `SYNTAX` — однозначно извлечено из дерева (сигнатуры, импорты, `impl Trait for Struct`).
  - `RESOLVED` — имя однозначно сопоставлено внутри файла или по прямому импорту.
  - `HEURISTIC` — сопоставление по имени метода в цепочках (`a.b().c()`) с фиксацией `confidence < 1.0`.
- **Декларативные Queries:** Использование tree-sitter queries (`.scm`, включая стандартные `tags.scm`) вместо ручного обхода узлов CST.
- **Инкрементальный парсинг:** Поддержка `Tree::edit` при изменениях файлов через watcher без повторного парсинга всего файла с нуля.
- **Бюджет размера:** Жесткий лимит на размер грамматик в бинарнике ($\le 8$ МБ на 4 языка суммарно).

### Столп II: Высокопроизводительный инференс и изоляция векторных пространств
- **Двухуровневый инференс:**
  - `Standard` (по умолчанию): Candle на CPU (чистый Rust, zero C-deps) + LRU-кэш.
  - `High-Performance` (`--features onnx`): FastEmbed / ORT с квантованными INT8 моделями (`bge-small-en-v1.5`, `all-MiniLM-L6-v2-quantized`).
- **Изоляция векторных пространств (Model Fingerprint):**
  - Векторы FP32 (Candle) и квантованные INT8 (ONNX) **несовместимы в одном индексе**.
  - В БД сохраняется мета-отпечаток `embedding_fingerprint` (`model_id:backend:quantization:dimension`).
  - При смене бэкенда или модели система блокирует смешанный поиск и требует фоновой переиндексации через `ob2h reindex --embeddings`.
- **Асинхронная изоляция:** Инференс векторов выносится из Tokio runtime в выделенный `EmbeddingWorkerPool` через `spawn_blocking` с семафором, предотвращая зависание MCP-запросов.
- **Безопасность:** Автоматическая маскировка (redaction) секретов, токенов и содержимого `.env` перед передачей в embedding-провайдеры и sync-бандлы.

### Столп III: Graph RAG 2.0 (Usage-Weighted Personalized PageRank)
- **База:** Развитие существующего механизма `src/graph/pagerank.rs` (power iteration, damping 0.5–0.85, dangling teleport).
- **Математически выверенная формула весов рёбер:**
  $$W(e) = W_0 \times \min\Big(1 + \ln(1 + \text{access\_count}),\ \text{CAP}_{\text{access}}\Big) \times e^{-\lambda_{\text{type}} \Delta t} \times (0.1 + 0.9 \times \text{trust\_score})$$
- **Защита от архитектурных дефектов:**
  1. *Анти-залипание («богатые богатеют»):* Жесткий cap на бонус обращений ($\text{CAP}_{\text{access}} = 3.0$) + периодическая нормализация и $\epsilon$-доля случайного исследования (*exploration*).
  2. *Дифференцированное затухание:* $\lambda_{\text{code}} = 0$ (стабильный код не устаревает; свежесть кода привязана к git commit/touch) vs $\lambda_{\text{memory}} > 0$.
  3. *Сохранение связности:* Множитель $(0.1 + 0.9 \times \text{trust})$ гарантирует, что даже при `trust = 0` ребро не исчезает физически и доступно для анализа причин устаревания.
  4. *CATD-lite:* Снижение скорости затухания для топологически нагруженных фактов (высокая степень связности, SOUL/USER-память).
  5. *Grace Period:* Новые узлы получают защиту от затухания на первые $N_{\text{grace}} \ge 4$ обращений (*cold-start trust*).
- **Производительность:** Расчет PPR ведется не на всем графе в 100k узлов, а на извлеченном $k$-hop сабграфе кандидатов (лимит 5k–10k узлов) с отсечением устаревших (`SUPERSEDED`) узлов.
- **Пакетная телеметрия:** Счётчики `access_count` аккумулируются в памяти и сбрасываются в SQLite пачками (раз в 10 с или при shutdown) во избежание блокировки `Mutex<Connection>`.

### Столп IV: Разрешение противоречий и актуализация знаний (Dream)
- **Таксономия конфликтов (3 типа отношений вместо простого «новое затирает старое»):**
  1. *Temporal Supersession* (факт А устарел и замещен фактом Б во времени).
  2. *User Correction* (пользователь явно исправил галлюцинацию или неточность агента — наивысший приоритет).
  3. *Contextual Coexistence* (факты кажутся противоречивыми, но верны в разных контекстах/проектах/окружениях).
- **Неразрушающая семантика (Tombstones & Lineage):**
  - Старые факты **не удаляются**. Создается направленное ребро `SUPERSEDES`, факт получает статус `valid_until` / tombstone.
  - Цепочки `SUPERSEDES` проверяются на идемпотентность (запрет циклов $A \to B \to A$).
- **Human-In-The-Loop (HITL):** Для фактов высокой важности (категории SOUL, USER, SYSTEM) авто-модификация запрещена — формируется предложение для ревью через `knowledge_reconcile`.
- **Защита бюджета и $O(N^2)$:** Ночной Dream проводит блокинг пар по категориям и порогу векторного сходства (cosine > 0.82), передавая на синтез только реальных кандидатов.
- **Rollback Gate (ADR-13):** Автоматический откат результатов ночного дриминга при падении метрик качества на golden-наборе более чем на 10%.

### Столп V: Высокопроизводительный векторный индекс (Vector Production)
- **Инкрементальный vec0:** Немедленный upsert векторов при записи узлов вместо долгой пакетной перестройки.
- **SIMD Rescore Pipeline:** Быстрый отбор top-200 кандидатов через легковесный скан $\to$ точный float rescore.
- **Партиционирование по пространствам имен:** Изоляция векторных индексов по `project_id` и типам (`memory` vs `graph`), что сокращает область поиска в 5–10 раз.

### Столп VI: Целостность цикла агента (Agent Loop Integrity)
- **Access Telemetry Parity:** Инкремент `access_count` и актуализация времени во всех точках касания: `memory_context`, `graph_reason`, prefetch-пути Hermes, `project_impact`, и при чтении артефактов Ralph.
- **Инвалидация устаревших findings Ralph:** При изменении сигнатур функций или рёбер AST-графа связанные выводы Ralph автоматически помечаются как `stale`.

### Столп VII: Кроссплатформенный Lifecycle-инсталлятор и деинсталлятор уровня Enterprise (Adobe/JetBrains-style)
- **Pre-flight & Hardware Telemetry (Глубокая диагностика окружения):**
  - Детекция возможностей процессора: инструкции AVX2, AVX-512, ARM NEON для выбора наиболее производительного рантайма ONNX.
  - Проверка и установка зависимостей: автоматическое фоновое развертывание Microsoft Visual C++ Redistributable (2015–2022) на Windows в тихом режиме (`vcredist_x64.exe /quiet /norestart`), проверка совместимости версий `glibc` и `OpenSSL` на Linux.
  - Детекция запущенных процессов: мягкая приостановка или запрос на завершение активных сессий `ob2h`, `hermes`, `claude` перед обновлением исполняемых файлов.
  - Проверка свободного места на диске с резервированием под локальный кэш моделей (~500 МБ).
- **Нативные пакеты вендорного класса для трех ОС:**
  - **Windows:** Установочный мастер (Setup Wizard) на базе Inno Setup / WiX v4 (MSI), поддержка тихого автоматического развертывания (`/SILENT`, `/VERYSILENT`, `/NORESTART`), регистрация в панели управления («Установка и удаление программ» / ARP) с отображением иконки, версии и издателя, публикация манифеста в Windows Package Manager (`winget install ob2h`).
  - **macOS:** Сборка универсального бинарника Universal2 (Intel + Apple Silicon), поставка в подписанном `.dmg` с фирменным Drag-and-Drop в `/Applications` и `.pkg` для Enterprise-дистрибуции, нотариальная заверка в Apple Notary Service (`xcrun notarytool` + `stapler`), публикация формулы Homebrew Cask (`brew install --cask ob2h`).
  - **Linux:** Полный набор пакетов: нативные `.deb` (Debian/Ubuntu) и `.rpm` (RHEL/Fedora), универсальный самодостаточный AppImage (со встроенными статическими библиотеками musl) и скрипт быстрой установки `curl -fsSL https://get.ob2h.dev | sh` с валидацией SHA256 и GPG-подписи.
- **Zero-Touch Provisioning (Авто-конфигурация системы и агентов):**
  - Автоматическое добавление `ob2h` в системный или пользовательский `PATH` без необходимости перезагрузки терминала.
  - Генерация и подключение автодополнений (shell completions) для PowerShell, Bash, Zsh, Fish.
  - Регистрация фонового демона ОС для ночного дриминга и фонового сканирования:
    - Windows: Служба Windows Service или задача Windows Task Scheduler (`ob2h-autodream`);
    - macOS: LaunchAgent (`~/Library/LaunchAgents/com.ob2h.agent.plist`);
    - Linux: Пользовательская служба `systemd --user` (`ob2h.service`).
  - **Zero-Touch IDE & Agent Auto-Discovery:** Сканирование системы и автоматическая прописка MCP-сервера `ob2h` во все обнаруженные AI-среды: Hermes (`config.yaml`), Claude Desktop (`claude_desktop_config.json`), Cursor (`mcp.json`), Windsurf, VS Code (Continue/Cline), Zed, Gemini CLI, Qwen. Обязательное создание бэкапа оригинальных конфигурационных файлов.
  - **First-Run Model Pre-Hydration:** Опциональная загрузка квантованных весов модели INT8 (MiniLM/BGE) прямо во время установки с прогресс-баром, гарантирующая нулевую задержку холодного старта при первом обращении агента.
- **Выделенный деинсталлятор вендорного класса (Enterprise Uninstaller Suite):**
  - **Нативный деинсталлятор:** Выделенный исполняемый файл `unins000.exe` на Windows (автоматически генерируется в каталоге установки), нативный сценарий `Uninstall OB2H.app` / деинсталляционный скрипт для macOS и Linux.
  - **Поддержка тихой деинсталляции:** Ключи `/SILENT`, `/VERYSILENT`, `/NORESTART` для корпоративных систем MDM (InTune, SCCM, Ansible).
  - **Шестишаговый цикл полного удаления (Full Teardown Cycle):**
    1. *Process Kill & Lock Release:* Обнаружение и корректное завершение фоновых воркеров, демонов и освобождение файловых блокировок (`ob2h.lock`, `autodream.lock`).
    2. *Daemon Unregistration:* Снятие задач Task Scheduler, удаление Windows Service, выгрузка LaunchAgent из `launchd`, деактивация и удаление `systemd --user` сервиса.
    3. *MCP Config Rollback:* Аккуратное удаление секции `"ob2h"` из конфигурационных файлов всех найденных агентов (Claude, Cursor, Windsurf, Hermes, VS Code, Zed) без повреждения настроек сторонних MCP-серверов.
    4. *Environment & Registry Scrub:* Удаление каталогов из системного/пользовательского `PATH` с рассылкой системного события `WM_SETTINGCHANGE` (без перезагрузки ОС), удаление автодополнений shell, очистка ключей реестра ARP (`HKCU`/`HKLM\Software\Microsoft\Windows\CurrentVersion\Uninstall\ob2h`).
    5. *User Data Governance (Диалог о данных Adobe/JetBrains-style):* Выбор режима в GUI-визарде или через CLI-флаги:
       - `--keep-data` (по умолчанию): сохраняет базу знаний `data/ob2h.db`, секреты Vault и историю; удаляет бинарники, службы и кэши.
       - `--purge-data` / `--scrub`: полное стирание всех файлов, включая БД, ключи шифрования, логи и локальные кэши моделей (`~/.cache/ob2h/models`, `%LOCALAPPDATA%/ob2h/models`).
    6. *Self-Deleting Execution on Windows:* Использование отложенного вспомогательного скрипта (watcher-процесса) для удаления самого исполняемого файла деинсталлятора и корневой директории приложения после завершения процесса.
- **Инструмент глубокой очистки (`ob2h cleaner` / Adobe Creative Cloud Cleaner Tool analog):**
  - Автономная аварийная консольная утилита для устранения поврежденных установок, зависших мертвых блокировок в реестре, некорректно удаленных служб и битых симлинков плагинов.

## 3. Нефункциональные требования (NFR)

| NFR | Целевой показатель v2.0 | Метод валидации |
|---|---|---|
| **Cold Start MCP** | < 100 мс (без ONNX load); ленивая загрузка ONNX по первому запросу | Интеграционный тест холодного старта |
| **Задержка поиска памяти (p95)** | < 50 мс при 50 000 memories (hybrid search) | `ob2h bench search` |
| **Задержка графового вывода (p95)** | < 200 мс при 100 000 узлов графа (U-PPR на сабграфе) | `ob2h bench graph` |
| **Скорость сканирования кода** | < 30 с на 100k LOC (первичное); < 3 с (инкрементальное через watcher) | Тест на `omnes-aibot` + `ob2h` |
| **Размер исполняемого файла** | $\le 25–30$ МБ (default); $\le 60–80$ МБ (`full` со всеми грамматиками и ONNX) | CI-проверка размера артефакта |
| **Потребление RAM в простое** | $\le 40$ МБ (default); $\le 150$ МБ (`full` с загруженной моделью в памяти) | Мониторинг RSS процесса |
| **Приватность и Offline** | 100% offline для ядра; внешние API только по явной настройке LLM; маскировка секретов | Unit-тесты `ApiEmbedding` + grep сетевых вызовов |
| **Детерминизм AST** | Идентичный вход $\to$ идентичные `node_id`, хеши и множество рёбер | Parity hash test на golden-репозиториях |
| **Crash Safety** | Аварийный kill процесса посреди Dream/Scan сохраняет консистентность БД | WAL checkpointing + транзакционные границы |
| **Развертывание (Zero-Touch Install)** | < 15 секунд в тихом режиме; возможность установки без прав root/Admin в user-space | Инсталляционный бенчмарк в чистых VM |
| **Чистота деинсталляции** | 100% удаление временных файлов, служб, записей реестра/PATH и откат MCP-конфигов | Проверка реестра и файловой системы после uninstall |

## 4. Матрица рисков и стратегии митигации

| Риск | Вероятность | Влияние | Стратегия митигации в v2.0 |
|---|:---:|:---:|---|
| **Проблемы линковки C-FFI / ONNX на Windows** | Высокая | Высокая | Feature flags отключены по умолчанию; сборка по умолчанию — чистый Rust. Для Windows CI — отдельный джоб с готовым runtime. |
| **Разрушение векторного поиска при смене бэкенда** | Средняя | Критическое | Хранение `embedding_fingerprint` в БД; блокировка поиска при несовпадении; CLI-команда `ob2h reindex --embeddings`. |
| **«Залипание» графа из-за петли U-PPR** | Высокая | Высокая | Жесткий cap бонуса обращений ($\text{CAP}=3.0$), exploration-ранжирование, разгрузка постоянного кода ($\lambda_{\text{code}}=0$). |
| **Ложные срабатывания детектора противоречий** | Средняя | Критическое | Режим предпросмотра (HITL) для важных фактов; трехуровневая таксономия (coexistence); запрет физического удаления данных. |
| **Квадратичный рост затрат на LLM в Dream** | Средняя | Средняя | Кандидаты отбираются вектором (cosine > 0.82) и категориями; суточный лимит токенов ($ budget); offline-режим без LLM. |
| **Устаревание артефактов Ralph при правках кода** | Высокая | Средняя | Автоматическая пометка `stale` findings в таблице Ralph при смещении хешей сигнатур AST. |
| **Разрастание размера бинарника из-за грамматик** | Средняя | Низкая | Включение грамматик только для топ-4 языков; остальные языки остаются на легковесном regex. |
| **Конфликты LWW при синхронизации счетчиков** | Средняя | Средняя | Использование CRDT-подобных монотонных счетчиков (`max(local, remote)`) для `access_count` и `trust_score`. |
| **Блокировка установки из-за отсутствия прав администратора** | Высокая | Средняя | Двухуровневый инсталлятор: User-space установка по умолчанию (`%LOCALAPPDATA%`, `~/.local/bin`) без UAC/root; опциональный системный режим. |
| **Блокировка неподписанных пакетов (SmartScreen, Gatekeeper)** | Высокая | Высокая | Интеграция подписи Authenticode для Windows и нотаризации Apple Developer ID для macOS в релизный CI-пайплайн. |
| **Фрагментация Linux (glibc vs musl, OpenSSL 1.1 vs 3.0)** | Средняя | Высокая | Поставка самодостаточного AppImage и статически слинкованного musl-бинарника наряду с `.deb`/`.rpm`. |
| **Повреждение конфигураций IDE при деинсталляции** | Средняя | Высокая | Точечный AST/JSON-парсер конфигов: вырезается только ключ `ob2h`; обязательное создание резервной копии `.bak` перед записью. |
