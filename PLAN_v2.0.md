# План разработки OB2H v2.0: Next-Gen Retrieval & Polyglot AST Engine

> **Версия плана:** 2.0.3 (Мажорный архитектурный релиз; ревизии: внешний аудит, вычитка и микро-аудит 2026-11-14)  
> **Статус:** Черновик к обсуждению и утверждению (Синтез рецензий v2.0 + Enterprise Lifecycle Installer & Uninstaller Suite + внешний аудит)  
> **Дата формирования:** 2026-10-25; ревизия 2026-11-14  
> **Базовое состояние:** v1.9.10 (патч поверх v1.9.9: viewer-полировка, тематические срезы графа, `.qoder/` в gitignore; Secrets Vault, Ralph Knowledge Layer, lifecycle lessons/slots/audit, native viewer; MCP-контракт **56** инструментов, схема БД v11/M11)  
> **Принцип совместимости и архитектурные границы:**  
> - Сохранение **ADR-1..8**: SQLite — единственная СУБД; никаких внешних серверов/демонов (Neo4j, Redis, Docker).  
> - Сохранение возможности **zero-dependency чистой сборки** (Candle + Regex fallback по умолчанию, компилятор C++ не требуется).  
> - Полная обратная совместимость схемы БД: автоматическая миграция **M12** (схема v11→v12; M10/M11 заняты релизами v1.9.9) с предварительным бэкапом и поддержкой dry-run.  
> - Аддитивное расширение MCP-контракта (существующие 56 инструментов сохраняют сигнатуры и семантику).  
> - **Честная политика Offline / LLM:** 100% локальное исполнение для парсинга AST, вычисления эмбеддингов, векторного поиска и графовых алгоритмов (U-PPR). Для LLM-операций дистилляции знаний (консолидация в Dream) предоставляется два режима: внешний API (DeepSeek/OpenAI), либо полностью автономный offline-режим (эвристические правила + косинусная семантическая близость без LLM).

## 1. Мотивация и предпосылки

К версии v1.9 `ob2h` сформировался как полнофункциональное персональное хранилище знаний, секретов и AST-графа проектов для AI-агентов. Однако при масштабировании на крупные кодовые базы (100k+ LOC), базы знаний (50k+ фактов) и широкий спектр рабочих окружений выявились архитектурные границы существующих решений:

| Компонент v1.x | Текущая реализация (As-Is) | Ограничение при росте | Целевое состояние v2.0 (To-Be) |
|---|---|---|---|
| **AST Parser** | Линейный regex/bracket-парсер | Не видит сложные цепочки вызовов `.foo().bar()`, макросы, типы в выражениях | **Tree-sitter Hybrid Engine** для топ-5 языков (Rust, TS/JS, Python, Go, Dart) с regex-fallback; `provenance` и `confidence` на рёбрах |
| **Embeddings** | Candle CPU (чистый Rust) + LRU-кэш | Холодный поштучный расчет 50–80 мс на CPU; синхронная блокировка Tokio | **FastEmbed / ONNX Runtime (INT8)** за feature-флагом, фоновый воркер-пул (`spawn_blocking`), батчи 32/64 чанка |
| **Vector Storage** | Линейный BLOB-скан + Cosine RRF | При >50k векторов O(N) перебор дает задержки >50 мс | **sqlite-vec / SIMD-ускорение**, инкрементальный upsert, двухступенчатый отбор (SIMD oversample $\to$ float rescore) |
| **Graph Retrieval** | BFS на $k$ шагов + FTS5 + векторный поиск | Нет ранжирования по живому опыту агента; шумные узлы не отсекаются | **Usage-Weighted PPR** с защитой от петли популярности, затуханием по типу сущности, CATD-lite и сабграф-кэшированием |
| **Жизненный цикл знаний** | Ручные пометки или простой decay | Накопление устаревших и конфликтующих фактов; split-brain агента | **Консолидация в Dream (3 типа конфликтов)**: `SUPERSEDES`/`CONTRADICTS`, HITL-preview, tombstone-семантика |
| **Agent Loop Integrity** | Разрозненные точки доступа к графу | PPR не видит реальные обращения из prefetch/Ralph; findings устаревают | **Access Telemetry Parity** по всем инструментам агента + авто-инвалидация устаревших findings Ralph при смене AST |
| **Установка и деинсталляция** | Ручная сборка `cargo build` или сырой архив, ручная настройка путей и MCP, неполное удаление | Высокий порог входа, поломка рантайм-зависимостей (VC++, glibc), мусор в реестре/PATH, поломка конфигов IDE при сносе | **Lifecycle через `cargo-dist`**: curl\|sh / PowerShell / Homebrew Tap / deb / rpm из одного конфига, user-space демоны (Task Scheduler / launchd / systemd --user), zero-touch IDE setup с JSONC-safe идемпотентным патчем, единая подкоманда `ob2h self uninstall` + `doctor --fix` вместо внешних деинсталляторов |

## 2. Ключевые архитектурные столпы v2.0

### Столп I: Гибридный полиглотный AST-движок (Tree-sitter + Regex)
- **Ядро:** Интеграция `tree-sitter` (0.27.x) через `tree-sitter-language` под опциональным feature-флагом `treesitter` для 5 основных языков: Rust, TypeScript/JavaScript, Python, Go, **Dart** (в личном стеке владельца Dart-проекты — без tree-sitter-dart они надолго остались бы на regex-парсере).
- **Fallback:** Существующий линейный regex-парсер сохраняется для остальных 15+ языков, а также включается при синтаксических ошибках (доля `ERROR`-узлов в CST > 10%).
- **CST vs Semantics:** Tree-sitter дает конкретное синтаксическое дерево (CST), но не вывод типов. Для графа вызовов вводится типизация достоверности связей (`provenance`):
  - `SYNTAX` — однозначно извлечено из дерева (сигнатуры, импорты, `impl Trait for Struct`).
  - `RESOLVED` — имя однозначно сопоставлено внутри файла или по прямому импорту.
  - `HEURISTIC` — сопоставление по имени метода в цепочках (`a.b().c()`) с фиксацией `confidence < 1.0`.
- **Декларативные Queries:** Использование tree-sitter queries (`.scm`, включая стандартные `tags.scm`) вместо ручного обхода узлов CST.
- **Макросы:** тела `macro_invocation`/декораторов (`tokio::select!`, роутеры `axum`, procedural-макросы) tree-sitter не раскрывает — вложенные идентификаторы извлекаются эвристически из `token_tree` с `provenance = HEURISTIC`.
- **Инкрементальный парсинг:** Поддержка `Tree::edit` при изменениях файлов через watcher без повторного парсинга всего файла с нуля. **LRU-кэш деревьев (32–64 последних изменённых файла)** — тотальное хранение CST-деревьев противоречит NFR по RAM ($\le 40$ МБ); для остальных полный ре-парсинг одного файла стоит 1–3 мс — быстрее и дешевле по памяти, чем сериализация дерева.
- **Бюджет размера:** Жесткий лимит на размер грамматик в бинарнике ($\le 8$ МБ на 5 языков суммарно; `tree-sitter-dart` ~1.2 МБ в бюджет вписывается).
- **Generated File Stubbing:** для генерированного кода (`*.g.dart`, `*.freezed.dart`, `*.pb.dart`, `*.pb.rs`, `*.generated.ts`) — только публичные сигнатуры верхнего уровня (`provenance = SYNTAX`); парсинг тел методов и векторизация чанков пропускаются, иначе build_runner/protobuf-вывод раздувает граф в 3–4 раза и забивает поиск дублями (детали — 70.15).

### Столп II: Высокопроизводительный инференс и изоляция векторных пространств
- **Двухуровневый инференс:**
  - `Standard` (по умолчанию): Candle на CPU (чистый Rust, zero C-deps) + LRU-кэш.
  - `High-Performance` (`--features onnx`): FastEmbed / ORT с квантованными INT8 моделями **мультиязычного/кодового класса** — `multilingual-e5-small` (INT8) либо `jina-embeddings-v2-base-code` / `nomic-embed-text-v1.5` (matryoshka-урезание до 256/384 dim). Строго англоязычные `bge-small-en-v1.5` / `all-MiniLM-L6-v2` основной моделью **не рассматриваются**: корпус RU/EN-смешанный, на русских комментариях и запросах их качество падает почти до шума; дефолтный Candle MiniLM остаётся legacy до прохода гейла RU/EN-триплетов (72.7).
- **Асимметричные префиксы модели:** `EmbeddingProvider` несёт `query_prefix`/`document_prefix` на уровне трейта и подставляет их автоматически (E5: `query: `/`passage: `; Nomic: `search_query: `/`search_document: `; Candle MiniLM и jina-v2 — no-op), чтобы вызывающий код о префиксах не думал. Индексация/поиск без префиксов роняет Recall@10 у E5 на 12–18% (детали — 72.2b).
- **Изоляция векторных пространств (Model Fingerprint):**
  - Векторы FP32 (Candle) и квантованные INT8 (ONNX) **несовместимы в одном индексе**.
  - В БД сохраняется мета-отпечаток `embedding_fingerprint` (`model_id:backend:quantization:dimension:prefix_vN` — версия префиксов/чанкера входит в отпечаток).
  - При смене бэкенда, модели, префиксов (72.2b) или схемы чанкинга (72.2a) система блокирует смешанный поиск и требует фоновой переиндексации через `ob2h reindex --embeddings`.
- **Асинхронная изоляция:** Инференс векторов выносится из Tokio runtime в выделенный `EmbeddingWorkerPool` через `spawn_blocking` с семафором, предотвращая зависание MCP-запросов.
- **Безопасность:** Автоматическая маскировка (redaction) секретов, токенов и содержимого `.env` перед передачей в embedding-провайдеры и sync-бандлы.

### Столп III: Graph RAG 2.0 (Usage-Weighted Personalized PageRank)
- **База:** Развитие существующего механизма `src/graph/pagerank.rs` (power iteration, damping 0.5–0.85, dangling teleport).
- **Математически выверенная формула весов рёбер:**
  $$W(e) = W_0 \times \min\Big(1 + \ln(1 + \text{access\_count}),\ \text{CAP}_{\text{access}}\Big) \times e^{-\lambda_{\text{type}} \Delta t} \times (0.1 + 0.9 \times \text{trust\_score})$$
- **Защита от архитектурных дефектов:**
  1. *Анти-залипание («богатые богатеют»):* Жесткий cap на бонус обращений ($\text{CAP}_{\text{access}} = 3.0$) + периодическая нормализация и $\epsilon$-доля случайного исследования (*exploration*).
  2. *Дифференцированное затухание:* $\lambda_{\text{code}} = 0$ (стабильный код не устаревает; свежесть кода привязана к git commit/touch) vs $\lambda_{\text{memory}} > 0$.
  3. *Сохранение связности:* Множитель $(0.1 + 0.9 \times \text{trust})$ гарантирует, что даже при `trust = 0` ребро не исчезает физически и доступно для анализа причин устаревания.
  4. *CATD-lite:* Снижение скорости затухания для топологически нагруженных фактов (высокая степень связности, SOUL/USER-память).
  5. *Grace Period:* Новые узлы получают защиту от затухания на первые $N_{\text{grace}} \ge 4$ обращений (*cold-start trust*).
  6. *Inverse In-Degree Penalty (HippoRAG-style):* базовый вес $W_0$ делится на $\ln(1 + \text{in\_degree}(v_{\text{target}}))$ для узлов кодового графа — иначе структурные хабы (`Error`, `Result`, `tracing::info`, `serde::Serialize`, `utils::*`) с тысячами входящих рёбер стягивают всю вероятностную массу PPR.
  7. *Взвешенная персонализация:* вектор $p_0$ от FTS5/векторных seeds задаётся не равномерным, а умноженным на `IDF` узла и его `trust_score`.
- **Производительность:** Расчет PPR ведется не на всем графе в 100k узлов, а на извлеченном $k$-hop сабграфе кандидатов (лимит 5k–10k узлов) с отсечением устаревших (`SUPERSEDED`) узлов.
- **Пакетная телеметрия:** Счётчики `access_count` аккумулируются в памяти и сбрасываются в SQLite пачками (раз в 10 с или при shutdown) **в транзакции `BEGIN IMMEDIATE`** — при 5–6 независимых процессах над одной БД (несколько MCP-серверов агентов, при DSH — два дочерних `ob2h`, фоновый `autodream`) иначе возникают `SQLITE_BUSY`. Единый контракт pragma для всех подключений (WAL и `busy_timeout` действуют с v0.x — фиксируются как инвариант): `journal_mode=WAL`, `synchronous=NORMAL`, `busy_timeout=5000`. Обслуживание WAL: периодический `PRAGMA wal_checkpoint(TRUNCATE)` + `PRAGMA optimize` в цикле autodream и при graceful shutdown MCP-сервера — постоянные читатели иначе блокируют усечение `ob2h.db-wal` (73.3).

### Столп IV: Разрешение противоречий и актуализация знаний (Dream)
- **Таксономия конфликтов (3 типа отношений вместо простого «новое затирает старое»):**
  1. *Temporal Supersession* (факт А устарел и замещен фактом Б во времени).
  2. *User Correction* (пользователь явно исправил галлюцинацию или неточность агента — наивысший приоритет).
  3. *Contextual Coexistence* (факты кажутся противоречивыми, но верны в разных контекстах/проектах/окружениях).
- **Неразрушающая семантика (Tombstones & Lineage):**
  - Старые факты **не удаляются**. Создается направленное ребро `SUPERSEDES`, факт получает статус `valid_until` / tombstone.
  - Цепочки `SUPERSEDES` проверяются на идемпотентность (запрет циклов $A \to B \to A$).
- **Human-In-The-Loop (HITL):** Для фактов высокой важности (категории SOUL, USER, SYSTEM) авто-модификация запрещена — формируется предложение для ревью через `knowledge_reconcile`.
- **Защита бюджета и $O(N^2)$:** Ночной Dream проводит блокинг пар по категориям **и обязательному Entity/Subject Overlap** (пересечение нормализованных сущностей, файлов/AST-путей, `project_id`) — на противоречие сравниваются только факты об *одном и том же объекте* (иначе «таймаут Auth 5с» и «таймаут Billing 5с» дадут cosine > 0.90 и сожгут бюджет LLM); лишь затем порог векторного сходства (cosine > 0.82).
- **Rollback Gate (ADR-13):** Автоматический откат результатов ночного дриминга при падении метрик качества на golden-наборе более чем на 10%.

### Столп V: Высокопроизводительный векторный индекс (Vector Production)
- **Инкрементальный vec0:** Немедленный upsert векторов при записи узлов вместо долгой пакетной перестройки.
- **SIMD Rescore Pipeline:** Двухступенчатый отбор: первая ступень — бинарное квантование (**mean-centered**: бит = `val > mean`, не `> 0.0` — компенсация анизотропии E5; маски `[u64; 6]` для 384 dim = 48 байт), кандидаты по Hamming distance (`popcnt(a ^ b)`, без C-FFI, < 0.5 мс на 100k векторов) $\to$ точный FP32/INT8 rescore top-200.
- **Партиционирование по пространствам имен:** Изоляция векторных индексов по `project_id` и типам (`memory` vs `graph`), что сокращает область поиска в 5–10 раз.

### Столп VI: Целостность цикла агента (Agent Loop Integrity)
- **Access Telemetry Parity:** Инкремент `access_count` и актуализация времени во всех точках касания: `memory_context`, `graph_reason`, prefetch-пути Hermes, `project_impact`, и при чтении артефактов Ralph.
- **Инвалидация устаревших findings Ralph:** При изменении сигнатур функций или рёбер AST-графа связанные выводы Ralph автоматически помечаются как `stale`.
- **Instant Negative Feedback (Mute Node):** агент разово оштрафовывает шумный/нерелевантный узел (`trust_score *= 0.3`) — множитель $(0.1 + 0.9 \times trust)$ в $W(e)$ роняет его на дно U-PPR уже на следующем шаге диалога, без ожидания ночного Dream.

### Столп VII: Кроссплатформенный Lifecycle-инсталлятор и деинсталлятор уровня Enterprise (Adobe/JetBrains-style)
- **Pre-flight & Hardware Telemetry (Глубокая диагностика окружения):**
  - Детекция возможностей процессора: инструкции AVX2, AVX-512, ARM NEON для выбора наиболее производительного рантайма ONNX.
  - Проверка зависимостей: VC++ Redistributable нужен **только сборке с `--features onnx`** (динамический `onnxruntime.dll`) — проверка и тихая установка `vcredist_x64.exe` гейтятся этим флагом; статическая сборка чистого Rust (`-C target-feature=+crt-static`) vcredist не требует. Для Linux статический musl-бинарник снимает вопрос совместимости `glibc`/`OpenSSL` целиком.
  - Детекция запущенных процессов: мягкая приостановка или запрос на завершение активных сессий `ob2h`, `hermes`, `claude` перед обновлением исполняемых файлов.
  - Проверка свободного места на диске с резервированием под локальный кэш моделей (~500 МБ).
- **Нативные пакеты вендорного класса для трех ОС:**
  - **Windows:** основной канал — `cargo-dist` (PowerShell-инсталлятор + portable exe в user-space). Опционально — один проверенный шаблон Inno Setup (ARP-регистрация, тихие флаги, при сносе вызывает `ob2h self uninstall --silent`) и манифест `winget`. Двойной стек Inno **и** WiX MSI снят: отладка WiX съедает недели, MSI — только при подтверждённом корпоративном спросе.
  - **macOS:** универсальный бинарник Universal2 (Intel + Apple Silicon), `cargo-dist`-тарбол + Homebrew Tap/Formula. Подписанные `.dmg`/`.pkg` и нотаризация Apple — **вне v2.0 по умолчанию**: требуют платного Developer ID ($99/год) и внешнего CI-сервиса; включать по явному решению владельца.
  - **Linux:** статический musl-бинарник в `.tar.gz`, `.deb` (`cargo-deb`) и `.rpm` (`cargo-generate-rpm`) — собираются минутами, `curl | sh` от `cargo-dist`. **AppImage убран:** консольному CLI/MCP-серверу без GUI он бесполезен и неудобен для прописки в `mcp.json`.
- **Zero-Touch Provisioning (Авто-конфигурация системы и агентов):**
  - Автоматическое добавление `ob2h` в системный или пользовательский `PATH` без необходимости перезагрузки терминала.
  - Генерация и подключение автодополнений (shell completions) для PowerShell, Bash, Zsh, Fish.
  - Регистрация фонового демона ОС для ночного дриминга и фонового сканирования:
    - Windows: **только** задача Windows Task Scheduler в контексте пользователя (`ob2h-autodream`) — Windows Service не вводим: требует UAC, живёт в Session 0 и не видит пользовательские пути IDE (`%USERPROFILE%\.cursor\mcp.json`);
    - macOS: LaunchAgent (`~/Library/LaunchAgents/com.ob2h.agent.plist`);
    - Linux: Пользовательская служба `systemd --user` (`ob2h.service`).
  - **Zero-Touch IDE & Agent Auto-Discovery:** Сканирование системы и автоматическая прописка MCP-сервера `ob2h` во все обнаруженные AI-среды: Hermes (`config.yaml`), Claude Desktop (`claude_desktop_config.json`), Cursor (`mcp.json`), Windsurf, VS Code (Continue/Cline), Zed, Gemini CLI, Qwen. Обязательное создание бэкапа оригинальных конфигурационных файлов. Патч **JSONC-safe и идемпотентен**: Cursor/Zed-`mcp.json` — JSON с комментариями и висячими запятыми, обычный `serde_json` при перезаписи их теряет; точечная вставка/вырезка ключа `ob2h` с сохранением комментариев (подход `jsonc-parser`/`toml_edit`, прецедент — маркерный патч cordis.patch.yml в DSH-установщике), тест round-trip: повторный install не меняет файл, uninstall восстанавливает.
  - **First-Run Model Pre-Hydration:** Опциональная загрузка квантованных весов выбранной INT8-модели (multilingual-e5-small / jina-code / nomic — Столп II; MiniLM — legacy) прямо во время установки с прогресс-баром, гарантирующая нулевую задержку холодного старта при первом обращении агента.
- **Деинсталляция — встроенная подкоманда CLI (вместо внешних деинсталляторов):**
  - `ob2h self uninstall [--keep-data | --purge-data] [--silent]` — весь шестишаговый teardown живёт в самом бинарнике; `unins000.exe` от Inno лишь вызывает её с `--silent`, MDM-совместимость — через флаги. Отдельных деинсталляционных бинарников и скрипт-вотчеров не плодим (объём поддержки −2/3).
  - **Шестишаговый цикл полного удаления (реализация внутри `self uninstall`):**
    1. *Process Kill & Lock Release:* Обнаружение и корректное завершение фоновых воркеров, демонов и освобождение файловых блокировок (`ob2h.lock`, `autodream.lock`).
    2. *Daemon Unregistration:* снятие задач Task Scheduler, выгрузка LaunchAgent из `launchd`, деактивация и удаление `systemd --user` сервиса (Windows Service не снимается — её не регистрируем);
    3. *MCP Config Rollback:* Аккуратное удаление секции `"ob2h"` из конфигурационных файлов всех найденных агентов (Claude, Cursor, Windsurf, Hermes, VS Code, Zed) без повреждения настроек сторонних MCP-серверов.
    4. *Environment & Registry Scrub:* Удаление каталогов из системного/пользовательского `PATH` с рассылкой системного события `WM_SETTINGCHANGE` (без перезагрузки ОС), удаление автодополнений shell, очистка ключей реестра ARP (`HKCU`/`HKLM\Software\Microsoft\Windows\CurrentVersion\Uninstall\ob2h`).
    5. *User Data Governance (диалог через флаги CLI, не GUI-визард):*
       - `--keep-data` (по умолчанию): сохраняет базу знаний `data/ob2h.db`, секреты Vault и историю; удаляет бинарники, службы и кэши.
       - `--purge-data` / `--scrub`: полное стирание всех файлов, включая БД, ключи шифрования, логи и локальные кэши моделей (`~/.cache/ob2h/models`, `%LOCALAPPDATA%/ob2h/models`).
    6. *Self-Deleting Execution on Windows:* удаление бинарника через отложенную само-замену (`self-replace`, уже в зависимостях ADR-15) — отдельного вотчера нет.
- **Аварийная очистка — расширение `ob2h doctor --fix` (вместо отдельного `cleaner`-бинарника):** проверка и снятие зависших блокировок, мёртвых задач планировщика, битых записей в конфигах IDE, сиротских процессов `ob2h` — по существующему паттерну doctor-проверок.

## 3. Нефункциональные требования (NFR)

| NFR | Целевой показатель v2.0 | Метод валидации |
|---|---|---|
| **Cold Start MCP** | < 100 мс (без ONNX load); ленивая загрузка ONNX по первому запросу — при этом первый поисковый запрос в момент прогрева не блокируется (degraded_mode, 72.5) | Интеграционный тест холодного старта |
| **Задержка поиска памяти (p95)** | < 50 мс при 50 000 memories (hybrid search) | `ob2h bench search` |
| **Задержка графового вывода (p95)** | < 200 мс при 100 000 узлов графа (U-PPR на сабграфе) | `ob2h bench graph` |
| **Скорость сканирования кода** | < 30 с на 100k LOC (первичное); < 3 с (инкрементальное через watcher) | Тест на `omnes-aibot` + `ob2h` |
| **Размер исполняемого файла** | $\le 25–30$ МБ (default); $\le 60–80$ МБ (`full` со всеми грамматиками и ONNX) | CI-проверка размера артефакта |
| **Потребление RAM в простое** | $\le 40$ МБ (default); $\le 150$ МБ (`full` с загруженной моделью в памяти) | Мониторинг RSS процесса |
| **Приватность и Offline** | 100% offline для ядра; внешние API только по явной настройке LLM; маскировка секретов | Unit-тесты `ApiEmbedding` + grep сетевых вызовов |
| **Детерминизм AST** | Идентичный вход $\to$ идентичные `node_id`, хеши и множество рёбер | Parity hash test на golden-репозиториях |
| **Crash Safety** | Аварийный kill процесса посреди Dream/Scan сохраняет консистентность БД | WAL checkpointing + транзакционные границы |
| **Развертывание (Zero-Touch Install)** | < 15 секунд в тихом режиме; возможность установки без прав root/Admin в user-space | Инсталляционный бенчмарк в чистых VM |
| **Чистота деинсталляции** | 100% удаление временных файлов, служб, записей реестра/PATH и откат MCP-конфигов | Проверка реестра и файловой системы после uninstall |

| **Блокировка установки из-за отсутствия прав администратора** | Высокая | Средняя | Двухуровневый инсталлятор: User-space установка по умолчанию (`%LOCALAPPDATA%`, `~/.local/bin`) без UAC/root; опциональный системный режим. |

| **Фрагментация Linux (glibc vs musl, OpenSSL 1.1 vs 3.0)** | Средняя | Высокая | Статический musl-бинарник (снимает вопрос целиком) + `.deb`/`.rpm`; AppImage не поставляем. |
| **SQLITE_BUSY при 5–6 процессах (мульти-MCP + DSH-дочерние + autodream)** | Средняя | Высокая | Единый контракт pragma (WAL, `synchronous=NORMAL`, `busy_timeout=5000`), `BEGIN IMMEDIATE` для пакетных сбросов телеметрии и vec0-upsertов, идемпотентные write-пути; плановый `wal_checkpoint(TRUNCATE)` + `PRAGMA optimize` (73.3) против starved-чекпойнтов и разбухания `ob2h.db-wal`. |
| **Повреждение конфигураций IDE при патче/деинсталляции (включая JSONC: комментарии, висячие запятые в Cursor/Zed `mcp.json`)** | Средняя | Высокая | Точечный JSONC/TOML-safe патч: вырезается только ключ `ob2h`, комментарии сохраняются; обязательный `.bak`; тест идемпотентности round-trip (install→uninstall = исходный файл). |

- [x] **72b.1** Инкрементальный upsert векторов в виртуальную таблицу `vec0` при изменении/добавлении узлов (отказ от полного пересчета). **Opt-in `OB2H_VEC0`** по итогам ADR-35.1 (эксперимент v1.4: recall@10 1.0, ×2.9 на векторе, но p95<50 мс не достигнут — SIMD-путь 72b.2 обязателен, vec0 его не отменяет); записи vec0 — в `BEGIN IMMEDIATE` (мульти-процессный доступ к БД).
- [x] **72b.2** Двухступенчатый конвейер извлечения: **ступень 1 — бинарное квантование (BQ, mean-centered):** бит = `val[i] > mean[i]` (перманентные per-dimension средние из выборки; fallback — скалярное среднее вектора `val[i] > vec_mean`), упаковка в битовые маски `[u64; 6]` (384 dim → 48 байт; 768 dim → 96 байт), хранятся рядом с вектором. Строгое `> 0.0` запрещено: у семейства E5 сильная анизотропия (μ_i смещены от нуля, например +0.08) — бит в ~80% векторов становится константой 1, и информационная ёмкость Hamming distance проседает; центрирование выравнивает 0/1 к 50/50 и поднимает бинарный Recall@200 на E5 с ~82% до 96–98% бесплатно. Отбор oversample-кандидатов (top-400–800) по Hamming distance `popcnt(a ^ b)` — чистый Rust без C-FFI, < 0.5 мс на 100k векторов; **ступень 2 — точный FP32/INT8 rescore** отобранных до итогового top-200 из БД. Закрывает требование p95 < 50 мс из ADR-35.1 без C-расширений.
- [ ] **72b.3** Партиционирование по пространствам имен: раздельные векторные индексы для `memories` и `ast_nodes` с фильтрацией по `project_id`.
- [ ] **72b.4** Регрессионный гейт: проверка recall@10 векторного поиска против brute-force эталона (ADR-13).
- [ ] **72b.5** Content-addressed кэш (blake3): таблица `file_blobs (blake3_hash PK, parser_version, embedding_fingerprint, ast_json, vector_ids)` — переключение git-веток (`main` ↔ `feat/x`) не вызывает шторм ре-парсинга и ONNX: при совпадении хеша переключаются указатели за миллисекунды. #### Фаза 73 — Usage-Weighted Personalized PageRank (U-PPR) (оценка: 3–4 дня)
- [ ] **73.1** Структура `GraphAdjacency`: компактное разреженное представление подграфа в памяти с весами рёбер.
- [ ] **73.2** Реализация формулы $W(e)$ в `src/graph/pagerank.rs`:
  - Ограничение бонуса популярности ($\text{CAP}_{\text{access}} = 3.0$);
  - Раздельные коэффициенты затухания: $\lambda_{\text{code}} = 0$ (код стабилен) vs $\lambda_{\text{memory}} > 0$;
  - Гарантированный ненулевой вес: $(0.1 + 0.9 \times \text{trust\_score})$;
  - In-Degree Penalty структурных хабов: $W_0 / \ln(1 + \text{in\_degree}(v_{\text{target}}))$;
  - Защита cold-start узлов (Grace period $N_{\text{grace}} \ge 4$);
  - Negative Feedback (Mute Node): разовый штраф узла агентом (`trust_score *= 0.3`) — через множитель $(0.1 + 0.9 \times trust)$ нерелевантный узел мгновенно проваливается на дно U-PPR уже на следующем шаге диалога, без ожидания ночного Dream.
- [ ] **73.3** Буферизация телеметрии обращений: накопление `access_count` в памяти с периодическим пакетным сбросом в БД. Вместе со сбросом — обслуживание WAL: `PRAGMA wal_checkpoint(TRUNCATE)` + `PRAGMA optimize` в цикле autodream и при graceful shutdown MCP-сервера (постоянные читатели не дают PASSIVE-чекпойнту усечь `ob2h.db-wal` — журнал растёт до сотен МБ).
- [ ] **73.4** Экстракция $k$-hop сабграфа: выделение кандидатов (до 5k–10k узлов) от FTS5 и векторных seeds для гарантированного соблюдения SLA < 20 мс; стартовый вектор $p_0$ — с взвешиванием `IDF` узла × `trust_score` (HippoRAG-style node specificity), не равномерный. **Active Working Set Boost:** узлы из файлов в `git diff HEAD` (изменены, ещё не закоммичены) получают буст +15–20% веса в $p_0$ — ранжирование держит фокус на текущей незакоммиченной работе.
- [ ] **73.5** Фильтрация устаревших данных: узлы с флагом `SUPERSEDED` исключаются из целевого вектора распределения PPR.
- [ ] **73.6** Сквозная телеметрия: регистрация обращений из `memory_context`, `graph_reason`, prefetch-вызовов Hermes и `project_impact`. Обратный канал — negative feedback (Mute Node, 73.2): разовый штраф `trust_score *= 0.3` из инструмента агента подавляет шумный узел сразу, не дожидаясь ночного Dream.
- [ ] **73.7** Калибровка весов на multi-hop golden наборе (сравнение выдачи с базовым PPR).
- [ ] **73.8** Токен-бюджетный AST-скелет: параметр `max_tokens` в `graph_reason`/`memory_context` — выдача компактного дерева «файл → сигнатура → вызываемые зависимости с confidence», упакованного строго под лимит контекста (1024/2048 токенов) и ранжированного U-PPR. **Не с нуля:** развитие существующего repo-map (v1.4 Ф36, PPR + binary-fit под token budget) — добавляется surface у `graph_reason` и скелет-рендер без тел функций. **Elbow / Drop-off Cutoff:** досрочная остановка упаковки при «мусорном хвосте» — вес узла $S_i < 0.15 \times S_{\text{max}}$ или соседний скачок вниз $> 50\%$ — даже если бюджет `max_tokens` не выбран (по узкому запросу не отдаём 1700 токенов шума после 3 релевантных узлов; экономия токенов агента и меньше галлюцинаций; прецедент — Vespa/Cohere dynamic score drop-off).
- [ ] **73.9** Sub-token декомпозиция идентификаторов в FTS5 (CamelCase/snake_case): токенизатор `unicode61` считает `EmbeddingWorkerPool` и `parse_source_file` неделимыми словами — запросы «worker pool»/«parse» не находят символы, и те не попадают в лексические seeds U-PPR (73.4). При записи символа в FTS5-индекс (scan-путь, канонизация 70.14) рядом пишется декомпозированная строка под-токенов («EmbeddingWorkerPool embedding worker pool»); колонка — в M12 (71.3). ≈2× точность лексических seeds кодового графа без смены токенизатора SQLite (прецедент — код-поиск Zulip/GitHub).
