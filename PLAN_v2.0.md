# План разработки OB2H v2.0: Next-Gen Retrieval & Polyglot AST Engine

> **Версия плана:** 2.0.0 (Мажорный архитектурный релиз)
> **Статус:** Черновик к обсуждению и утверждению
> **Дата формирования:** 2026-10-25
> **Предыдущие этапы:** v1.9.0 (Secrets Vault, Ralph Knowledge Layer, FTS5 Graph, LRU-кэш, багфиксы)
> **Принцип совместимости:** 
> - Полная обратная совместимость схемы БД (миграция **M10** / `SCHEMA_VERSION = 10`).
> - Аддитивное расширение MCP-контракта (существующие 41 инструмент не ломаются).
> - Сохранение ADR-1..8: SQLite остаётся единственной СУБД, никаких внешних серверов/демонов (Neo4j, Redis, Docker).
> - Сохранение возможности zero-dependency чистой сборки (ONNX/Tree-sitter подключаются через feature flags или изолированные адаптеры).

---

## 1. Мотивация и предпосылки

К версии v1.9 `ob2h` сформировался как полнофункциональное хранилище знаний, секретов и AST-графа проектов для AI-агентов. Однако при масштабировании на крупные кодовые базы (100k+ строк кода) и базы знаний (50k+ фактов) выявились архитектурные границы текущих движков:

| Компонент v1.x | Текущая реализация v1.9 | Ограничение при росте | Цель в v2.0 |
|---|---|---|---|
| **AST Parser** | Линейный regex/bracket-парсер | Не видит сложные вызовы методов, цепочки `.foo().bar()`, замыкания, макросы, типы в сложных выражениях | **Tree-sitter Hybrid Engine** для топ-4 языков (Rust, TS, Python, Go) с regex-fallback |
| **Embeddings** | Candle CPU (чистый Rust) + LRU-кэш | Холодный расчет вектора 50-100 мс на CPU; медленный батчинг больших проектов | **FastEmbed / ONNX Runtime (INT8)** опция: инференс 10-15 мс (3-6x ускорение) |
| **Graph Retrieval** | BFS на $k$ шагов + FTS5 + векторный поиск | Нет ранжирования по «авторитетности» и живому опыту агента; шумные узлы не отсекаются | **Usage-weighted PPR (Personalized PageRank)** с затуханием по времени и числу обращений |
| **Vector Storage** | Линейный BLOB-скан + Cosine RRF | При объеме >50k эмбеддингов линейный перебор начинает занимать >50 мс | **sqlite-vec / SIMD-ускорение** векторного индекса внутри SQLite |
| **Жизненный цикл знаний** | Ручные пометки или простой decay | Накопление противоречивых фактов со временем; агент путается в устаревших инструкциях | **Автономная консолидация в Dream**: авто-резолв противоречий, рёбра `SUPERSEDES` |

Цель v2.0: превратить `ob2h` в промышленный **высокопроизводительный локальный Graph & Code Intelligence хаб**, не жертвуя при этом простотой развертывания и приватностью.

## 2. Ключевые архитектурные столпы v2.0

### Столп I: Гибридный полиглотный AST-движок (Tree-sitter + Regex)
- **Ядро:** Интеграция `tree-sitter` (через Rust C-FFI биндинги) для языков с глубокой и сложной грамматикой:
  - **Rust** (`tree-sitter-rust`)
  - **TypeScript / JavaScript** (`tree-sitter-typescript`)
  - **Python** (`tree-sitter-python`)
  - **Go** (`tree-sitter-go`)
- **Fallback:** Существующий легковесный regex/bracket-парсер сохраняется для остальных 15+ языков (PHP, Ruby, C/C++, Java, C#, Bash, SQL, Dockerfile, YAML, Kotlin, Swift и др.).
- **Возможности нового AST:**
  - Точный трекинг цепочек вызовов (`a.b().c()`).
  - Разрешение перегрузок, реализаций трейтов/интерфейсов (`impl Trait for Struct`).
  - Выделение контекста докстрингов, аннотаций типов и сигнатур аргументов без ложных срабатываний.
  - Построение графа зависимостей на уровне выражений (Expression-level Call Graph).

### Столп II: Высокопроизводительный инференс эмбеддингов
- **Двухуровневая архитектура:**
  - **Default (Standard):** Встроенный `Candle` (чистый Rust, работает везде без установки C++ библиотек) + LRU-кэш.
  - **Feature-flag `onnx` (High-Performance):** `fastembed` / `onnxruntime` с поддержкой квантованных моделей INT8 (`bge-small-en-v1.5`, `all-MiniLM-L6-v2-quantized`).
- **Батчинг и многопоточность:**
  - Пул фоновых воркеров для параллельного эмбеддинга сотен файлов при первичном сканировании проектов без фриза MCP-запросов.

### Столп III: Graph RAG 2.0 (Usage-Weighted Personalized PageRank)
- **Алгоритм U-PPR:**
  - Random Walk with Restart (RWR) по графу знаний и кода.
  - Веса рёбер зависят от:
    $$W(e) = W_0 \times (1 + \ln(1 + \text{access\_count})) \times e^{-\lambda \Delta t} \times \text{trust\_score}$$
  - Быстрое итеративное приближение (Power Iteration с ранней остановкой при $\epsilon < 10^{-4}$ за <20 мс).
- **Смысл для LLM:** Агент получает из графа только те сущности, которые не просто формально связаны по имени, но реально используются и актуальны в текущем контексте работы.

### Столп IV: Разрешение противоречий и Knowledge Distillation
- **Интеллектуальный ночной воркер (`dream_run`):**
  - Поиск взаимно исключающих утверждений в `memories` и `graph_nodes`.
  - Автоматическое связывание ребром `CONTRADICTS`.
  - Запуск микро-промпта через `llm_client` для формулирования синтеза («Факт А устарел и заменён фактом Б»).
  - Создание ребра `SUPERSEDES` и снижение веса доверия к старому факту до нуля.

## 3. As-Is vs To-Be (Сравнение характеристик)

| Параметр | ob2h v1.9 | ob2h v2.0 |
|---|---|---|
| **Точность AST-графа** | 80-85% (на сложных конструкциях и макросах возможны пропуски) | **99% для топ-4 языков** (настоящие деревья синтаксиса) |
| **Межфайловые связи** | `ast_refs` по сигнатурам функций и точным импортам | Полноценный граф вызовов методов, трейтов и типов |
| **Скорость эмбеддинга CPU** | 50-80 мс (Candle) / 0 мс на кэше | **10-15 мс** (FastEmbed INT8) / 0 мс на кэше |
| **Масштабируемость графа** | До 10 000 узлов без лагов | **До 100 000+ узлов** (U-PPR + sparse storage) |
| **Актуальность знаний** | Ручное удаление/обновление + tombstone | **Автоматическое вытеснение противоречий** в цикле Dream |
| **Сборка проекта** | Чистый `cargo build` | `cargo build` (default) / `cargo build --features onnx,treesitter` |

## 4. Фазы реализации v2.0

### Фаза 70 — Фундамент гибридного AST (Tree-sitter Core) (оценка: 3 дня)
- [ ] **70.1** Подключение `tree-sitter` в `Cargo.toml` под опциональную фичу `treesitter` (с возможностью сборки со статическими парсерами для Rust, Python, TypeScript, Go).
- [ ] **70.2** Абстракция `AstParserTrait`: единый интерфейс разбора `parse_source(path, content) -> AstFileResult` для унификации tree-sitter и regex-бэкенда.
- [ ] **70.3** Реализация парсера Rust на `tree-sitter-rust`: точный разбор `impl`, макросов, сигнатур функций, модулей и `use`-импортов.
- [ ] **70.4** Реализация парсера TypeScript/JS на `tree-sitter-typescript`: стрелочные функции, классы, интерфейсы, типы, ESM/CJS импорты.
- [ ] **70.5** Реализация парсера Python на `tree-sitter-python`: async-функции, декораторы, классы, относительные импорты.
- [ ] **70.6** Реализация парсера Go на `tree-sitter-go`: структуры, интерфейсы, методы структур, пакеты.
- [ ] **70.7** Бенчмарки и регрессионные тесты: сравнение производительности и точности на реальных репозиториях (`ob2h`, `omnes-aibot`).

### Фаза 71 — Глубокий Call Graph & Expression Tracking (оценка: 2 дня)
- [ ] **71.1** Извлечение вызовов методов объектов (`obj.method()`) и цепочек вызовов через обход узлов CST (`CallExpression`).
- [ ] **71.2** Индексация реализации трейтов и интерфейсов: построение рёбер `IMPLEMENTS` между структурами и интерфейсами/трейтами в таблице `ast_edges`.
- [ ] **71.3** Миграция БД **M10**: добавление колонок `ast_nodes.kind_detail`, `ast_edges.confidence`, расширение типов рёбер (`IMPLEMENTS`, `OVERRIDES`, `INSTANTIATES`).
- [ ] **71.4** Интеграция с MCP-инструментом `project_impact`: точный расчёт радиуса поражения (Blast Radius) с учётом виртуальных вызовов и трейтов.

### Фаза 72 — FastEmbed & Batch Vector Pipeline (оценка: 2 дня)
- [ ] **72.1** Опциональный крейт `fastembed` / `ort` под флагом `onnx`: загрузка квантованной INT8 модели `all-MiniLM-L6-v2`.
- [ ] **72.2** Пул фоновых потоков `EmbeddingWorkerPool` для пакетной обработки текстовых чанков (батчи по 32/64 вектора).
- [ ] **72.3** Авто-выбор бэкенда при запуске: если доступна библиотека ONNX — использование FastEmbed, иначе — прозрачный fallback на встроенный Candle.
- [ ] **72.4** CLI-команда `ob2h bench embeddings`: замер скорости инференса векторов на текущем оборудовании пользователя.

### Фаза 73 — Usage-Weighted Personalized PageRank (U-PPR) (оценка: 2.5 дня)
- [ ] **73.1** Структура данных `GraphAdjacency`: разреженное представление подграфа в памяти с весами рёбер.
- [ ] **73.2** Логирование использования узлов: авто-инкремент `access_count` и обновление `last_accessed_at` при возврате фактов агенту в `memory_context` и `graph_reason`.
- [ ] **73.3** Реализация алгоритма Power Iteration PPR:
  - Вектор предпочтений (personalization vector) инициализируется узлами, найденными через FTS5 и векторный поиск.
  - Расчёт стационарного распределения за $N \le 15$ итераций с коэффициентом возврата $\alpha = 0.85$.
- [ ] **73.4** Интеграция U-PPR в `graph_reason`: узлы в ответе агенту ранжируются с учётом их глобального графового веса и свежести.
- [ ] **73.5** Юнит- и интеграционные тесты U-PPR на тестовых графах знаний (проверка подавления изолированных/устаревших узлов).

### Фаза 74 — Автономная дистилляция знаний и разрешение конфликтов (оценка: 2 дня)
- [ ] **74.1** Ночной детектор противоречий в `DreamWorker`: выявление пар фактов одной категории с высокой семантической близостью, но противоположными предикатами.
- [ ] **74.2** Механизм `ContradictionSynthesizer`: генерация лаконичного разрешения через `llm_client` (выбор более позднего факта как истинного).
- [ ] **74.3** Автоматическая простановка рёбер `SUPERSEDES` и `CONTRADICTS`.
- [ ] **74.4** MCP-инструмент `knowledge_reconcile`: ручной или автоматический аудит выявленных конфликтов с подтверждением пользователя при необходимости.

### Фаза 75 — Интеграция, релизная упаковка и документация (оценка: 1.5 дня)
- [ ] **75.1** Настройка кросс-платформенного CI (`.github/workflows/ci.yml`): сборка Release бинарников под Windows (x86_64), Linux (x86_64, aarch64) с матрицей фич (`default` и `full`).

- **Архитектурные гарантии:**
  - Полная сохранность локального характера работы (никаких облаков и сторонних серверов).
  - Сборка по умолчанию остаётся чистой без внешних C++ библиотек (Candle + Regex fallback).
  - Включение `features = ["onnx", "treesitter"]` активирует максимальный уровень скорости и точности для production рабочих станций.
