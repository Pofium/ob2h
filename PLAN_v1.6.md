## 1. Мотивация

System One — класс моделей, которые не генерируют текст, а за один проход возвращают
типизированное решение (выбор из вариантов / балл / калиброванную вероятность) за десятки
миллисекунд. В ob2h есть минимум три места, где сегодня решение принимает либо
дорогой LLM-вызов, либо ничего (голый порядок RRF):

| Место | Как сейчас (факт по коду) | Цена сегодня | Чем закрываем |
|---|---|---|---|
| Ранжирование `memory_search` | `search_hybrid_hits` (src/memory/service.rs:588): FTS5 + vector → `rrf_merge(k=60)` → топ-`limit`. Порядок внутри одинаковых RRF-рангов произволен | baseline Ф21 (живая БД): search recall@5 = 0.222 / MRR = 0.198; контекст-путь 0.833/0.861 — у явного поиска запас качества не выбран | **Ф43**: реранк топ-N кандидатов вопросом Noul «запись отвечает на запрос?» |
| Консолидация merge-кандидатов | `consolidate_merge_candidates` (src/dream/consolidate.rs:89): каждый кандидат `meta.merge_candidate` = отдельный LLM-вызов `ask_json` с вердиктом `merge/keep_both/contradicts/supersedes` | LLM-вызовы на ночь, бюджет и задержка растут линейно с числом почти-дублей | **Ф44**: пре-вердикт Laya до LLM — уверенные «не-дубли» не доходят до LLM |
| Очередь candidate_for_forget | trust < 0.15 даёт маркер, но очередь не отсортирована по «действительно устарела» | дрим тратит внимание на шум | **Ф44**: скоринг очереди (рекомендательный, авто-удалений нет — правило владельца) |

**Почему Laya, а не другие открытые System One модели** (полный разбор — §8):

- candle-transformers **0.8 уже в Cargo.toml** и уже содержит реализацию ModernBERT
  (`models/modernbert.rs` в крейте — проверено в локальном реестре) → **ноль новых
  crate-зависимостей**; Laya = safetensors энкодера + голова-декодер поверх него.
- 421M параметров: CPU-инференс за десятки–сотни мс, приемлемо для PC и VPS.
- Мультиязычность (100+ языков): память ob2h в основном на русском — Nimble
  (англоцентричный LoRA на Qwen3.5-9B) здесь не конкурент; для 9B на нашем железе
  нет ни GPU, ни смысла (секунды на решение).
- Apache-2.0, веса на HF, RP (мультиязычная модель в репо — `multilingual/`).

**Почему не хостед Jev:** ADR сети («только LLM/embedding API, OpenAI-совместимые»);
evaluate-эндпоинт TypeSafe — отдельная сеть и внешний сервис. Отклонено для дефолта
(§7); переоткрыть может только владелец записью в PLAN.md §6.

## 2. Архитектурный обзор v1.6

```
   ┌──────────────────────────────────────────────────────────────┐
   │  src/s1/ (новый модуль)                                      │
   │  contract.rs  — Question/Answer/Batch (Choice/Score/Noul)    │
   │  provider.rs  — trait SystemOne { decide(state, questions) } │
   │  fake.rs      — детерминированный стаб (тесты, отладка)      │
   │  laya.rs      — CandleLayaProvider: modernbert.rs + head     │
   │  log.rs       — журнал решений data/s1/decisions.jsonl       │
   └──────────────┬───────────────────────────────┬───────────────┘
                  │ (выключено по умолчанию)      │
   ┌──────────────▼──────────────┐   ┌────────────▼────────────────┐
   │ Ф43: реранк memory_search   │   │ Ф44: дрим-гейты             │
   │ после rrf_merge: топ-N →    │   │ 31.2: пре-вердикт дублей    │
   │ Noul «релевантна?» →        │   │ до LLM; сортировка очереди  │
   │ пересортировка + порог      │   │ candidate_for_forget        │
   └──────────────┬──────────────┘   └─────────────────────────────┘
                  │
   ┌──────────────▼──────────────────────────────────────────────┐
   │ Ф45: MCP-инструмент `s1` (37-й) — прямой доступ агента      │
   │ Ф46: замеры на копии БД → решение о дефолтах v1.6.x         │
   └──────────────────────────────────────────────────────────────┘

   Кэш модели: ~/.cache/huggingface/hub/ (тот же паттерн, что у MiniLM);
   офлайн-оверрайд: OB2H_S1_PATH на локальный каталог чекпойнта.
```

Разделение ролей: Laya — **быстрый фильтр и сортировщик**, вердикт-арбитр — по-прежнему
LLM (дрим) или владелец (memory_merge). Laya никогда не выполняет деструктивное действие
самостоятельно; её вероятности — вход в чужое решение.

## 3. Модель данных и файлы

**Миграций НЕТ (M9 не вводится).** Схема SQLite не меняется: решения логируются файлом,
реранк и дрим-гейты — чистые read-path поверх существующих таблиц.

| Файл/артефакт | Назначение | Ротация |
|---|---|---|
| `data/s1/decisions.jsonl` | журнал решений: ts, caller (rerank/dream/mcp), state_hash (sha256, не текст), question, answer, probs, duration_us, model_id | по `OB2H_LOG_RETENTION_DAYS` (общий механизм логов) |
| `data/s1/bench_report.md` | отчёт Ф46 (числа до/после, p50/p95) | перезаписывается прогоном |
| `~/.cache/huggingface/hub/models--convaiinnovations--laya/` | веса (model.safetensors + tokenizer + encoder/config.json + rl_agent_config.json) | вне бэкапов ob2h |

Жёсткие ограничения совместимости:
- Таблицы `memories`, `memory_links`, проекции, `sync_state` — не трогаются. Реранк не
  трогает access-счётчики (пересортировка ПОСЛЕ их инкремента в существующем коде).
- Бандлы sync v2 не расширяются: s1-лог — локальный артефакт, через синк не ходит.
- Контракт плагина: тест на число инструментов обновляется 36 → 37 (Ф45), сам плагин
  (`plugin/ob2h/*.py`) не меняется.

## 4. Детальные фазы реализации

### Фаза 41: контракт System One + провайдер-трейт + фейк

- [ ] 41.1 Новый модуль `src/s1/`: `contract.rs` — типы `Question` (enum: `Choice{options}` /
  `Score{levels: u8}` / `Noul`), `Answer` (выбранный вариант/уровень/вероятность +
  `Vec<f32>` распределение + `confidence`), `Batch` (state: String/JSON-объект +
  Vec<Question>). Сериализация serde, имена полей как у Laya SDK (`choice/score/noul`,
  `confidence`).
- [ ] 41.2 `provider.rs` — `trait SystemOne: Send + Sync { fn decide(&self, state:
  &S1State, questions: &[Question]) -> anyhow::Result<Vec<Answer>>; fn model_id(&self)
  -> &str; }`. Никакой сети в трейте: провайдер получает готовый текст.
- [ ] 41.3 `fake.rs` — `FakeSystemOne`: детерминированный стаб (hash-based ответы,
  настраиваемая карта вопрос→ответ), для юнит-тестов гейтов — по образцу
  `embedding/fake.rs` и `llm/fake.rs`.
- [ ] 41.4 Конфиг (src/config.rs, паттерн `OB2H_*`): `OB2H_S1_PROVIDER` (`off` | `laya` |
  `fake`, дефолт `off`), `OB2H_S1_PATH` (локальный каталог чекпойнта, офлайн-оверрайд),
  `OB2H_S1_DEVICE` (`cpu`), `OB2H_S1_MAX_TOKENS` (дефолт 512, обрезка входа), `OB2H_S1_LOG`
  (`1` — журнал включён, дефолт `0`).
- [ ] 41.5 `provider_for(settings)` — фабрика по образцу `embedding::provider_for`:
  `off` → `None` (все вызовы должны быть `if let Some(s1)`); `fake` → стаб; `laya` →
  CandleLayaProvider. Ошибка загрузки модели → warn + деградация в `off` (С-1).

**Тесты фазы:** контрактные тесты serde-круговорота Question/Answer; FakeSystemOne
детерминирован; фабрика: неизвестное значение провайдера → `off` + warn (не panic);
`OB2H_S1_MAX_TOKENS=0` валидируется и поднимается до минимума.

### Фаза 42: CandleLayaProvider (Laya в Candle)

- [ ] 42.1 `src/s1/laya.rs`: загрузка `encoder/config.json` + `model.safetensors` +
  токенизатора из HF-кэша (hf-hub, уже в зависимостях) или `OB2H_S1_PATH`. Энкодер —
  `candle_transformers::models::modernbert::ModernBert` (0.8).
- [ ] 42.2 Голова: описание архитектуры головы Laya (тип, форму, имена весов) —
  прочитать из `rl_agent_config.json`/`typed-decisions/` чекпойнта ДО кодинга (задача
  разведки — отдельный первый пункт чеклиста Ф42, результат — в комментарии модуля);
  если голова реализуется поверх pooled-выхода энкодера — Linear-слой в Candle
  вручную из весов safetensors. **Gate:** если архитектура головы не восстанавливается
  из чекпойнта без torch (форма/имена нечитаемы) — фаза останавливается, в план
  пишется факт, выполняется Ф42-alt (ONNX-путь, §7).
- [ ] 42.3 Инференс: один forward энкодера на state → пул → головы вопросов; answer =
  argmax распределения; вероятности softmax; Noul = P(true). Батч вопросов — один
  проход энкодера (вопрос-критерии — часть промпта каждого вопроса; допускается
  K проходов «энкодер+голова» при схеме Laya «одна голова на вопрос»: зафиксировать
  фактическую схему в комментарии).
- [ ] 42.4 Ограничения: вход > `OB2H_S1_MAX_TOKENS` токенов → обрезка (head+tail
  сохранение начала и конца); `decide` синхронный CPU — вызывать из async-контекста
  через `spawn_blocking` (токен-лимит на конкурентность не нужен при десятках мс, но
 Semaphore-обёртка на 4 параллельных вызова — на усмотрение реализации).
- [ ] 42.5 `model_id()` = `convaiinnovations/laya` + ревизия из кэша.

**Тесты фазы:** (без сети, на фикстуре) загрузка чекпойнта из tmp-каталога с
минимальным фиктивным ModernBERT-чекпойнтом → forward даёт корректную форму
распределений (softmax-сумма = 1, размерности по схеме); обрезка длинного входа;
`spawn_blocking`-обёртка не блокирует рантайм (tokio-тест). Интеграционный тест с
реальными весами — `#[ignore]`-тест `s1_laya_real`, запускается вручную после
`hf download convaiinnovations/laya` (не в CI, не в `cargo test` по умолчанию).

### Фаза 43: реранк memory_search (Флаг, дефолт OFF)

- [ ] 43.1 В `search_hybrid_hits` после `rrf_merge` и до формирования hits: если s1
  активен И `OB2H_S1_RERANK=1` — топ-`min(limit*3, 50)` кандидатов (id + заголовок +
  body-фрагмент до 700 символов) → Batch с одним Noul-вопросом «Эта запись отвечает
  на запрос пользователя?» → пересортировка: primary key = noul_p, tie-break = rrf_score.
- [ ] 43.2 Порог отсечения `OB2H_S1_RERANK_MIN_P` (дефолт 0.5): кандидаты ниже порога
  удаляются из выдачи, ЕСЛИ после удаления остаётся ≥1 кандидат (иначе порог
  игнорируется — анти-«пустой ответ»).
- [ ] 43.3 Access-счётчики: реранк выполняется после штатного инкремента (не менять
  порядок существующих side-эффектов); реранк не считает access повторно.
- [ ] 43.4 Журнал: caller=`rerank`, state_hash, noul_p, итоговый порядок (первые 10 id).
- [ ] 43.5 Поиск-путь `search_vector` (чистый векторный) НЕ реранжируется в v1.6.0
  (только гибрид — он основной для MCP `memory_search`); отметить в комментарии.

**Тесты фазы:** юнит на `search_hybrid_hits` с FakeSystemOne: пересортировка
соответствует ответам фейка; порог: все ниже порога → порог игнорируется (не пусто);
детерминизм: два вызова на одной БД — идентичный порядок; при провайдере `off` —
байт-в-байт прежнее поведение (регресс-тест на существующем наборе golden — `cargo
test` целиком зелёный).

### Фаза 44: дрим-гейты (пре-вердикт дублей, сортировка очереди forget)

- [ ] 44.1 `consolidate_merge_candidates`: перед LLM-вызовом по паре (A,B) — Laya-Noul
  «Запись B — то же знание, что A?»; P(не-дубль) ≥ `OB2H_S1_DREAM_MIN_P` (дефолт 0.85) →
  вердикт `keep_both` БЕЗ LLM (маркер снимается, отчёт: `{caller: "dream", verdict:
  "keep_both_by_s1"}`); иначе — как сейчас, LLM решает.
- [ ] 44.2 Явный `memory_merge` НЕ автоматизируется: он уже подтверждён владельцем.
  Деструктивные исходы (`merge/supersedes` в дриме) — только LLM, Laya не предлагает их
  в v1.6.0.
- [ ] 44.3 Очередь `candidate_for_forget`: сортировка скорингом Noul «Запись устарела /
  противоречит более свежим знаниям?» (только порядок, количество выбывших не меняется;
  верх списка — рекомендации владельцу/дриму).
- [ ] 44.4 В дрим-отчёт — блок `s1: {prefiltered: N, llm_saved: N, sorted: N}`.

**Тесты фазы:** с FakeSystemOne (запрограммирован «не-дубль»): LLM не вызывается
(FakeLLM считает вызовы), маркер снят, `keep_both_by_s1` в отчёте; с фейком «дубль» —
LLM вызывается как раньше; `provider=off` — поведение байт-в-байт прежнее; сортировка
forget-очереди стабильна и не меняет состав.

### Фаза 45: MCP-инструмент `s1` (37-й) + контракт

- [ ] 45.1 `src/mcp/tools.rs`: описание инструмента `s1` (state + до 8 вопросов;

- [ ] 45.2 `src/mcp/server.rs`: `handle_s1` — валидация (число вопросов, размеры опций,

- [ ] 45.3 Журнал: caller=`mcp`. Обновить счётчик 36 → 37 в README/ARCHITECTURE/

- [ ] 45.4 Задержка: p95 `s1` на типовом вызове логируется в omnes_stats (kv `s1:p95_us`).

**Тесты фазы:** контракт-тест плагина на 37; E2E через `s1` с fake-провайдером

## 7. Отклонённые альтернативы

| Альтернатива | Причина отклонения |
|---|---|
| Хостед Jev (TypeSafe evaluate API) как дефолт | Нарушает ADR сети ob2h (только LLM/embedding API). Возможен как опциональный провайдер в будущем — новым решением владельца (запись §6), не этим планом |
| Bespoke Nimble-9B | 9B на CPU = секунды на решение (теряется смысл System One); англоцентричные тренировочные данные; GPU-требования |
| Kev/NanoJev (кастомные головы поверх Qwen) | Головы не переиспользуют llama.cpp/candle-стек без своего инференс-пути; интересны позже как «обучить свой S1 на своих логах» (бэклог) |
| ONNX-экспорт Laya (ort-крейт) | Новая зависимость + новый рантайм; Candle-путь уже в стеке. **Резерв (Ф42-alt)**, если голова не восстанавливается из чекпойнта (см. 42.2 Gate) |
| Реранк в `search_vector` и `build_context` | Горячий путь контекста трогаем только после данных Ф46 (риск регрессии recall 0.833/0.861). Вынесено в v1.6.x за флагом |
| Ретрайн/дообучение под домен памяти | Не в v1.6; кандидаты Kev-подхода — в бэклоге |
