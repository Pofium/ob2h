## 3. Архитектурные границы (нарушение = ошибка)

Закреплены ADR-1…ADR-8 в `PLAN.md` §1. Кратко, что это значит на практике:

- **SQLite — единственная СУБД.** Никаких Postgres, Neo4j, Redis, Docker.
- **Без torch/transformers.** Эмбеддинги — `fastembed` (ONNX) или API.
- **Вектора — BLOB + numpy-перебор.** sqlite-vec — только в бэклоге (см. ADR-2).
- **Сеть — только LLM/embedding API** (OpenAI-совместимые) и ничего более.
- **Один пользователь, без RBAC/компаний/мультиарендности** — это осознанно вырезано
  из портируемого кода, не возвращать.
- **Vendored OpenSPG/KAG (`services/kag`, `services/knext`) из omnes-aibot не переносить
  никогда.** Реальный пайплайн OmnesBOT — OneKE-экстракция + `KAGReasoningService` (см. REFERENCE).

## 5. Команды

```bash
python -m venv .venv                          # однократно
.venv/Scripts/pip install -e ".[dev]"         # после смены зависимостей
.venv/Scripts/pytest                          # тесты (перед каждым коммитом)
.venv/Scripts/ruff check src tests            # линт (перед каждым коммитом)
.venv/Scripts/python -m ob2h.server   # ручной запуск MCP-сервера
```

- Windows, Git Bash. Пути в коде — через `pathlib.Path`; не хардкодить `C:\...`.
- Runtime-пути (БД, workspace, логи) берутся из конфига `OB2H_*`, дефолты — внутри
  `data/` проекта.

## 6. Правила кода

- **Python 3.12+** (синтаксис и библиотеки должны работать на 3.12 и 3.14).
- Типизация аннотациями обязательна на публичных функциях/методах; `pydantic v2` для
  схем и конфига.
- Асинхронность: MCP-слой async; SQLite — синхронный доступ через один поток/lock
  (SQLite не любит конкурентные писатели; обёртка — в `db.py` с фазы 1).
- **Ошибки инструментов MCP — возвращаемая строка `[Error] <что случилось> [Подсказка]`,
  не исключение.** Исключения внутри — логировать.
- Комментарии/докстринги — русские, краткие, только там, где код не очевиден.
  Имена — английские, snake_case.
- Портированный код **упрощается при переносе**: убрать company/user/RBAC/Postgres/Neo4j-
  ветки, leave только локальный путь. Не копировать файлы целиком ради одной функции.
- Секреты — только через env (`OB2H_LLM_API_KEY` и т.п.). В коде и тестах ключей нет;
  `.env` в `.gitignore`; примеры — `OB2H_LLM_API_KEY=...`.
- Зависимости: прежде чем добавить — проверить, что она есть в `pyproject.toml` и
  обоснована (лёгкая, без транзитивных гигантов). Новая зависимость = запись в `PLAN.md` §6.
- Любой LLM-вызов в коде идёт через `llm_client.py` (ретраи, таймауты, логи) — никаких
  прямых httpx-вызовов к API из других модулей.
- Изменение контракта MCP-инструментов (имя/аргументы/семантика) — только с записью в
  `CHANGELOG.md`.

## 7. Правила тестирования

- Тесты пишутся вместе с фичей (см. DoD фаз в `PLAN.md`); каждый юнит-тест без сети.
- Внешние LLM в тестах заменяются `FakeLLM` (стаб в `tests/fakes.py`, создаётся в фазе 3;
  до этого фазы 1–2 не требуют LLM вовсе).
- Эмбеддинги в тестах — фиксированные векторы (детерминированная заглушка), fastembed
  не нужен. Реальный fastembed — отдельные `@pytest.mark.embeds`-тести, skip при
  отсутствии пакета.
- Тестовая БД — `:memory:` или tmp_path. Никогда — `data/ob2h.db`.

## 8. Git

- Коммиты — малые, после каждой задачи/подзадачи: `feat(4.2): экстрактор сущностей из чанков`,
  `fix(2.1): RRF k=60 как в MemoryService`, `docs: ...`, `test: ...`, `refactor: ...`.
- Ветка `main`, пуш не нужен (локальный проект). `.gitignore` не трогать без причины.
- `data/.git` (workspace-репозиторий дрима) — отдельный git, не связанный с этим;
  в `.gitignore` проекта он исключён.

## 9. Безопасность и приватность

- Это личные данные пользователя (история, память). Ничего не отправлять никуда,
  кроме настроенного LLM/embedding API. Никакой телеметрии, аналитики, авто-обновлений.
- Не читать чужие конфиги/данные вне таблицы §1 — в том числе «просто посмотреть».
- Файлы бэкапов (`backups/`) содержат те же персональные данные — не публиковать,
  в git не включать.

## 10. Чеклист перед завершением любой задачи

1. Тесты на новую логику написаны и зелёные, весь `pytest` не сломан.
2. `ruff check` чисто.
3. DoD задачи/фазы в `PLAN.md` выполнен, чекбокс закрыт.
4. Коммит(ы) оформлены по §8.
5. Если решение отклонилось от плана — строка в `PLAN.md` §6.
6. Публичный контракт инструментов не менялся молча (иначе — `CHANGELOG.md`).
