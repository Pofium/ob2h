Two independent plugin implementations share one runtime: `plugin/ob2h/` is a Python `MemoryProvider` (`Ob2hProvider`) that launches `ob2h serve` via stdio JSON-RPC, while `plugin/dsh-ob2h/` is a Node.js cordis plugin exporting `apply`/`install` with the same semantics. Both communicate with the same Rust binary through their own RPC layers (`_rpc.py::Ob2hRpc` and `lib/rpc.js::Ob2hRpc`). The Python side exposes lifecycle hooks (`sync_turn`, `queue_prefetch`, `on_session_end`, `on_pre_compress`, `get_tool_schemas`, `handle_tool_call`) and runs a background writer thread plus a health loop; the JS side hooks into cordis events (`agent/pre-step`, `session/event`) to inject `<agent_memory>` snapshots and capture turns. Configuration resolution is parallel in both stacks — from `ob2h.json`, env vars (`OB2H_BIN`, `OB2H_DATA_DIR`, `OB2H_LLM_*`), PATH, and a Windows dev fallback — so either host can locate the binary independently. Tests under each sub-package use a shared `fake_server` pattern to mock the child process.
